# mcpmake — Project Guidance (`.impeccable.md`)

Durable positioning and standards so contributors (human or agent) stop drifting
between "owned-code compiler" and "anything self-serve automation."

## What mcpmake is

A compiler that turns an API description **you already have** into a clean, typed,
**editable MCP server you own** — no runtime dependency on mcpmake, Apache-2.0 in and out.

## Product promise boundaries (do NOT overclaim)

- **Primary, deterministic inputs — lead with these:** OpenAPI/Swagger, Postman, HAR,
  Stainless config, live-URL capture. Spec/traffic-driven, reproducible, well tested.
- **Experimental, best-effort inputs — label as such:** whole-website (browser) capture and
  plain-English `describe`. Browser/LLM-driven, high-variance across real sites/prompts.
  Never presented as a peer to the deterministic paths.
- **Sync = the self-hosted `mcpmake ci init [--pr]` workflow only.** It regenerates on spec
  change, drift-checks, and (with `--pr`) opens a maintenance PR. There is **no** managed
  centralized multi-repo sync service and **no** policy-check engine — do not put those words
  in pricing, README, or UI. (`packages/core/test/pricing.test.ts` blocks the phrasing.)
- **Registry publish** generates manifests (mcp.so/Smithery/Glama/official) and shells out to
  `mcp-publisher`; it is not validated against live registries end-to-end. Say "generate
  registry manifests," not "publish to every registry," until live publish is proven.

## Pricing truth

Source of truth is `packages/core/src/pricing.ts` (`FAMILY_A_PRICING`) + the live
`/api/pricing` backend. Keep tier summaries to shipped truth — the tests in
`packages/core/test/pricing.test.ts` guard both the floors and the phrasing.

## Copy tone

Plain, concrete, engineer-to-engineer. Lead with ownership ("code you own, no lock-in").
No hype adjectives, no capability the code doesn't ship. When a path is experimental, say so
in the same breath you introduce it.

## CLI / UX standards

- Every operator-supplied value that reaches a shell/git/YAML context is allowlist-validated
  and must not start with `-` (see `assertCiSafe` in `packages/cli/src/commands/ci.ts`).
- Generated output is deterministic (same inputs → byte-identical); collisions fail loudly,
  never silently last-write-wins (`emitter/code-writer.ts`, `emitter/normalize-tree.ts`).
- Fail closed on secrets/channels: HTTPS-only for tokens, redact on error, `.env` denylist.
- Releases run the full gate (format + typecheck + unit + built-bin e2e + prod audit) via
  `publish.yml` OR the hardened `npm run publish:all`. Never publish from an ungated path.
